## 1. 문서 목적

이 문서는 `docs/img/aT_Brand_System.md`, 제공된 로고·사옥 이미지, 현재 메인 홈페이지 소스를 바탕으로 aT 메인 홈페이지 개선 방향과 제품 요구사항을 정의한다.

개선의 핵심은 현재의 콘텐츠형 랜딩 페이지를 다음 세 가지 역할이 명확한 공공 서비스 홈으로 전환하는 것이다.

1. 방문자가 자신의 상황에 맞는 지원사업과 정보를 빠르게 찾는다.
2. aT의 공공 역할과 전문성을 공식 CI, 정확한 데이터, 실제 현장 이미지로 신뢰하게 된다.
3. 생산–유통–소비–수출을 연결하는 aT의 브랜드 아이디어가 화면 구조와 인터랙션에서 일관되게 드러난다.

## 2. 제품 배경

### 2.1 브랜드 핵심

브랜드 시스템이 정의한 aT의 핵심은 다음과 같다.

- **Brand Idea:** 농수산식품의 더 나은 흐름을 만드는 공공 플랫폼
- **Purpose:** 농어업과 시장, 대한민국과 세계를 연결해 더 나은 먹거리 생태계를 만든다.
- **Core Values:** 책임감, 혁신, 지속가능, 전문성
- **Personality:** Trusted, Expert, Connected, Progressive, Sustainable
- **UX Keywords:** Clear, Trusted, Fast, Inclusive
- **Core Motif:** Flow — 생산 → 유통 → 소비 → 세계를 잇는 흐름

따라서 홈페이지는 홍보 문구를 길게 보여주기보다 사용자의 행동, 공공 데이터의 근거, 기관의 연결 역할을 먼저 보여줘야 한다.

### 2.2 현재 제품 상태

현재 앱은 서버·데이터베이스 없이 `src/data/mockData.ts`의 정적 데이터를 사용하는 React 프로토타입이다. 홈은 12개 섹션으로 구성되어 있고, 탭 전환도 URL 라우팅이 아닌 `App.tsx`의 상태로 처리한다.

현재 구현에서 유지할 가치가 있는 요소는 다음과 같다.

- 농어업인, 기업, 수출기업, 국민을 구분한 사용자 중심 진입점
- 지원사업 대상별 필터
- 농수산물 가격과 산업 데이터 모듈
- 블로그·농산물 검색 및 북마크
- 생산–유통–소비–수출의 연결 서사
- 반응형 레이아웃과 모바일 메뉴

다만 브랜드와 제품 신뢰 관점에서 즉시 수정해야 하는 문제도 존재한다.

| 현재 상태 | 문제 | 개선 방향 |
|---|---|---|
| 사과와 들판을 합성한 3D `aT` 이미지를 로고로 사용 | 공식 CI와 다르며 공공기관 신뢰 훼손 가능 | 공식 aT CI 파일로 전면 교체 |
| serif·italic·영문 대문자 장식이 반복됨 | 브랜드의 명확하고 쉬운 공공 UI 원칙과 충돌 | Pretendard/Noto Sans KR 중심으로 단순화 |
| 히어로에 CTA 3개와 가치 단계 4개가 동시에 노출 | 첫 행동의 우선순위가 불명확 | 핵심 CTA 1개 + 보조 CTA 1개로 축소 |
| 홈이 12개 섹션으로 길게 이어짐 | 핵심 서비스 발견 전에 정보 피로 발생 | 8개 핵심 블록으로 재구성 |
| 공지 항목을 눌러도 모두 동일한 모달 표시 | 선택한 정보와 결과가 일치하지 않음 | 실제 선택 공지 상세 연결 |
| 화면상의 신청·구독·댓글이 서버로 전송되지 않음 | 실제 기능처럼 보이면 신뢰 문제 발생 | 실제 API 연동 또는 명확한 데모 표시 |
| `/src/assets/...` 문자열 경로 사용 | 프로덕션 빌드에서 이미지 누락 가능 | 정적 import 또는 `public` 자산으로 이전 |
| 탭과 상세 화면이 URL에 반영되지 않음 | 새로고침·뒤로 가기·공유·SEO 불가 | URL 라우팅 및 딥링크 도입 |

## 3. 문제 정의

### P1. 사용자가 “나에게 필요한 일”로 바로 진입하기 어렵다

현재 첫 화면은 기관 설명과 3개의 CTA를 동시에 제시한다. 사용자는 aT의 조직 구조보다 “내가 신청할 수 있는 사업”, “오늘의 가격”, “수출 지원”, “공고”를 먼저 찾고 싶다.

### P2. 공식성과 시각적 신뢰가 충분하지 않다

현재 로고 자산은 공식 CI와 다른 합성형 이미지이며, 일부 사옥·농가 이미지도 출처와 실제성 검증이 필요하다. 공공기관 홈페이지에서 로고와 사진의 진위·권리 문제는 시각적 취향이 아니라 출시 적합성 문제다.

### P3. 콘텐츠는 많지만 우선순위와 근거가 약하다

가격, 성과, 지원 규모 등이 표시되지만 기준일·출처·갱신 주기가 일관되게 제시되지 않는다. 브랜드 시스템의 “데이터와 출처를 명확히 한다”는 원칙을 충족하지 못한다.

### P4. 정보 탐색 결과가 실제 상세 행동으로 이어지지 않는다

지원사업·공지·데이터 카드가 공통 모달로 연결되거나 데모 상태에 머문다. 사용자가 상세보기, 자격 확인, 신청, 원문 보기까지 완결할 수 있는 흐름이 필요하다.

## 4. 목표와 비목표

### 4.1 제품 목표

1. 첫 방문자가 10초 안에 자신에게 맞는 핵심 진입점을 찾게 한다.
2. 지원사업 탐색에서 대상·기간·혜택·신청 행동을 한 흐름으로 제공한다.
3. 공식 CI와 검증된 사진을 적용해 공공기관의 신뢰와 전문성을 강화한다.
4. 가격·성과·수출 데이터에 기준일, 단위, 출처를 일관되게 표시한다.
5. 모바일과 키보드 환경에서도 주요 업무를 동등하게 완료할 수 있게 한다.
6. 메인 화면의 각 모듈을 API 데이터로 교체 가능한 구조로 만든다.

### 4.2 비목표

이번 메인 홈페이지 개선 범위에는 다음을 포함하지 않는다.

- 모든 하위 업무 시스템의 완전한 재구축
- 공식 CI 자체의 재디자인
- 전자신청·본인인증·결제 백엔드 구축
- KAMIS, KATI 등 외부 시스템의 내부 기능 재개발
- 전체 블로그 편집 시스템 또는 CMS 구축
- 공식 수치와 사업 공고의 내용 확정

단, 메인 화면에서 해당 시스템으로 안전하고 명확하게 연결되는 사용자 흐름은 범위에 포함한다.

- 현재 접수 가능한지 즉시 알 수 있어야 한다.
- 내부 약어보다 쉬운 표현을 먼저 봐야 한다.
- 링크를 눌렀을 때 예상한 정보가 나와야 한다.
- 숫자에는 기준일과 출처가 있어야 한다.
- 모바일에서도 전화번호, 기간, 신청 버튼이 읽기 쉬워야 한다.

## 6. 경험 원칙

### 6.1 Action First

기관 설명보다 “지원사업 찾기”, “가격 확인”, “수출 정보 보기” 같은 사용자 행동을 먼저 제시한다.

### 6.2 Evidence Builds Trust

성과와 데이터에는 반드시 기준일, 단위, 출처, 상세 링크를 함께 제공한다.

### 6.3 One Screen, One Decision

한 섹션은 하나의 핵심 메시지와 하나의 주 행동을 갖는다. 같은 위계의 CTA를 과도하게 나열하지 않는다.

### 6.4 Flow as Function

‘Flow’는 배경 장식에만 쓰지 않는다. 사용자가 생산, 유통, 소비, 수출의 관계를 이해하고 관련 서비스로 이동하는 정보 구조로 구현한다.

### 6.5 Inclusive by Default

쉬운 한국어, 충분한 글자 크기, 44px 이상의 터치 영역, 키보드 조작, 색상 외 상태 표기를 기본값으로 한다.

## 7. 제안 정보 구조

현재 12개 홈 섹션을 아래 8개 핵심 블록으로 재편한다.

```text

2. 히어로: 브랜드 약속 + 핵심 행동

7. 현장·글로벌 사례 + 기관 신뢰
8. 공지·보도자료 + 푸터
```

1. 사업안내
2. 지원사업
3. 농수산식품정보

## 8. 섹션별 제품 요구사항

## 8.1 공공 알림과 헤더

### 목적

공식 기관임을 분명히 하고, 긴급 공고·고객상담·핵심 메뉴를 빠르게 제공한다.

### 요구사항

- 공식 aT 가로형 CI를 헤더 왼쪽에 사용한다.
- 로고 전체 영역은 홈 링크이며 접근 가능한 이름을 제공한다.
- 상단 알림은 실제 공고 제목, 상태, 종료일을 데이터로 받아 표시한다.
- 공고가 없을 때는 빈 띠를 유지하지 않고 상단 알림 영역을 숨긴다.
- 공고 클릭 시 해당 공고 상세 URL로 이동한다.
- 고객상담 번호는 `tel:` 링크와 운영시간을 함께 제공한다.
- 데스크톱에서는 6개 주 메뉴, 모바일에서는 전체메뉴 드로어를 제공한다.
- 현재 위치는 색상뿐 아니라 밑줄과 `aria-current="page"`로 표시한다.
- 스크롤 고정 헤더 높이는 데스크톱 72px 이하, 모바일 64px 이하로 유지한다.

### 완료 기준

- 합성형 사과 `aT` 이미지가 어떤 화면 크기에서도 노출되지 않는다.
- 모바일 360px 폭에서 로고, 검색, 메뉴 버튼이 한 줄에서 겹치지 않는다.
- 모든 헤더 기능을 키보드만으로 사용할 수 있다.

## 8.2 히어로

### 목적

aT가 무엇을 연결하는 기관인지 한 문장으로 이해시키고, 가장 중요한 사용자 행동으로 안내한다.

### 제안 카피

**Eyebrow**  
한국농수산식품유통공사

**Headline**  
농수산식품의 더 나은 흐름을 만듭니다

**Body**  
생산자에게는 더 큰 시장을, 산업에는 성장의 기반을, 국민에게는 안정적인 먹거리를 연결합니다.

**Primary CTA**  
내 지원사업 찾기

**Secondary CTA**  
농수산식품 정보 보기

### 요구사항

- 동일 위계 CTA는 최대 2개로 제한한다.
- 히어로 아래 또는 내부에 사용자 유형 선택 칩을 제공한다: 농어업인, 기업, 수출기업, 국민.
- 선택한 유형은 지원사업 섹션 필터와 연동한다.
- 히어로 이미지 위 텍스트는 WCAG AA 대비를 만족한다.
- 큰 반투명 박스가 사진 대부분을 가리지 않게 한다.
- 자동 재생 슬라이더는 사용하지 않는다.
- 모션은 300ms 이하의 단순 등장 효과로 제한하며 `prefers-reduced-motion`을 준수한다.

### 이미지 방향

브랜드의 1순위 사진 주제는 실제 현장의 사람과 먹거리다. 현재 제공 자료는 사옥·로고 중심이므로, 출시용 히어로에는 별도의 공식 현장 사진 확보가 필요하다.

- 권장: 실제 농어업인과 생산 현장이 보이며 텍스트 여백이 있는 16:9 원본
- 임시 대안: `회사2.webp` 사옥 전경을 사용하되, 기관 소개 성격이 강하다는 한계를 감수
- 지양: 출처가 불명확한 합성 사옥 이미지, 워터마크 이미지, 저해상도 로고 합성 이미지

## 8.3 사용자별 빠른 서비스

### 목적

방문자가 조직 구조를 이해하지 않아도 자신의 상황으로 서비스를 찾게 한다.

### 카드 구성

| 사용자 유형 | 대표 링크 |
|---|---|
| 농어업인 | 판로·유통 지원, 산지 지원, 수급·가격 정보, 정책사업 |
| 식품·유통·외식기업 | 기업 지원, R&D, 유통, 사업자 공고 |
| 수출기업 | 수출지원, 시장정보, 바이어, 박람회 |
| 국민·소비자 | 가격정보, 식품정보, 공공급식, 정책정보 |

### 요구사항

- 전체 카드가 클릭 가능해야 하며 카드 내부에 중복 버튼을 두지 않는다.
- 각 카드에는 최대 3개의 대표 업무와 “전체 서비스 보기” 링크만 둔다.
- 아이콘은 동일한 Lucide 계열과 스트로크 규칙을 사용한다.
- 사용자가 유형을 선택하면 아래 지원사업 필터 상태에 반영하고 결과 위치로 이동한다.
- 모바일에서는 가로 스크롤보다 1열 또는 2열 그리드를 우선한다.

## 8.4 현재 신청 가능한 지원사업

### 목적

가장 전환 가치가 높은 지원사업을 대상별로 찾고 실제 공고·신청으로 이동하게 한다.

### 필수 정보

- 사업명
- 대상
- 신청 기간과 마감까지 남은 날짜
- 지원 혜택 또는 규모
- 접수 상태
- 담당 부서
- 상세보기
- 원문 공고 또는 신청하기

### 요구사항

- 기본값은 `접수중`인 전체 사업이며, 마감일이 가까운 순으로 정렬한다.
- 대상 필터는 농어업인, 식품기업, 수출기업, 유통기업, 외식기업을 제공한다.
- `접수중`, `마감임박`, `상시접수`, `접수마감`을 텍스트와 형태로 구분한다.
- 마감된 사업은 기본 목록에서 후순위로 배치하고 신청 CTA를 비활성화한다.
- 지원사업 상세 모달은 URL을 가져야 하며 새로고침과 링크 공유가 가능해야 한다.
- 모달에는 Escape 닫기, 포커스 트랩, 닫힌 후 원래 버튼으로 포커스 복귀를 구현한다.
- 실제 신청 링크가 없으면 `신청하기`를 표시하지 않는다.

## 8.5 오늘의 농수산식품 데이터

### 목적

aT의 데이터 전문성을 짧고 신뢰할 수 있는 정보로 증명하고 전문 포털로 연결한다.

### 모듈 구성

1. 주요 품목 가격
2. 수급 동향
3. 수출 현황
4. 식품산업 지표

### 요구사항

- 모든 수치에 기준일, 단위, 출처를 표시한다.
- 등락은 색상만이 아니라 화살표, 부호, 텍스트를 함께 사용한다.
- 상승이 항상 좋은 의미가 아니므로 `초록=상승` 같은 의미 고정을 피한다.
- 가격 정보는 KAMIS, 수출 정보는 KATI 등 원천 서비스명을 명확히 표시한다.
- 데이터 갱신 실패 시 마지막 갱신 시각과 오류 상태를 표시한다.
- 카드 클릭 시 해당 데이터의 실제 상세 페이지로 이동한다.
- 홈에는 결론만 보여주고 복잡한 차트는 상세 페이지로 넘긴다.

## 8.6 aT 핵심사업 Flow

### 목적

수급안정, 유통혁신, 수출진흥, 식품산업 육성이 서로 연결된 하나의 가치사슬임을 설명한다.

### 요구사항

- 네 사업을 독립된 반복 로고 카드가 아니라 연결된 단계 또는 노드로 표현한다.
- 데스크톱에서는 생산 → 유통 → 소비/산업 → 세계로 이어지는 가로 흐름을 사용한다.
- 모바일에서는 위에서 아래로 읽는 세로 흐름으로 전환한다.
- 각 단계는 짧은 혜택 문장과 관련 서비스 링크를 갖는다.
- 연결선은 장식이 아니라 읽기 순서와 관계를 표현해야 한다.
- 공식 로고를 사업 카드마다 반복하지 않는다.

## 8.7 현장·글로벌 사례와 기관 신뢰

### 목적

정책 이름이 아니라 실제 사람·현장·성과로 aT의 공공 가치를 보여준다.

### 요구사항

- 사례는 인물, 지역, 지원 내용, 변화 지표를 한 세트로 보여준다.
- 성과 수치에는 기간과 산정 기준을 제공한다.
- 농업인을 전통적이거나 수혜적인 대상으로만 묘사하지 않고 전문 생산자·사업 파트너로 표현한다.
- 글로벌 사례는 K-Food 제품과 현지 시장 맥락을 함께 보여준다.
- 사옥 이미지는 기관 소개 또는 신뢰 블록에 제한적으로 사용한다.
- ESG는 별도 장식 카드보다 구체적 목표·성과·보고서 링크로 구성한다.

## 8.8 공지·보도자료와 푸터

### 목적

최신 공공정보와 기관 필수 정보를 정확히 제공한다.

### 요구사항

- 공지, 사업공고, 보도자료, 채용 탭을 제공한다.
- 목록 항목 클릭 시 선택한 항목의 실제 상세를 연다.
- 긴급 여부, 게시일, 담당 부서를 표시한다.
- 전체 목록 링크를 각 탭 문맥에 맞게 제공한다.
- 푸터에는 기관 주소, 대표전화, 개인정보처리방침, 저작권, 관련 사이트, 공식 SNS를 제공한다.
- 뉴스레터가 실제 연동되지 않는 단계에서는 구독 폼을 제거하거나 “준비 중”으로 명시한다.

## 10. 비주얼 시스템 요구사항

## 10.1 컬러

브랜드 시스템의 작업용 팔레트를 토큰으로 구현한다. 최종값은 공식 CI 매뉴얼 확인 후 확정한다.

| Token | 값 | 사용 |
|---|---|---|
| `--color-brand-teal` | `#09524D` | 헤더, 주요 CTA, 핵심 수치 |
| `--color-growth-green` | `#488835` | 성장·농업 강조 |
| `--color-field-green` | `#97AF79` | 보조 그래픽 |
| `--color-fresh-mist` | `#CDDEC8` | 정보 구분 배경 |
| `--color-charcoal` | `#2B2F2F` | 본문 텍스트 |
| `--color-white` | `#FFFFFF` | 기본 배경 |
| `--color-harvest-red` | `#C83A32` | 긴급·핵심 CTA의 제한적 강조 |

### 컬러 적용 원칙

- 흰색/밝은 중립색 60–70%
- Deep Teal 15–20%
- Growth Green 10–15%
- 기타 강조색 5% 이하
- 현재 코드의 `#2C4A3E`, `#1E332B`, `#A2A67C` 반복값은 토큰으로 통합하고 공식 팔레트에 맞춰 조정한다.
- 상태는 색상뿐 아니라 아이콘과 텍스트를 함께 사용한다.

## 10.2 타이포그래피

- 기본 국문: Pretendard, 대안 Noto Sans KR, 시스템 sans-serif
- 영문·숫자: Inter 또는 국문 폰트와 조화되는 sans-serif
- H1: 700, 데스크톱 56–64px / 모바일 36–40px
- H2: 600–700, 데스크톱 36–44px / 모바일 28–32px
- 본문: 400, 데스크톱 16–18px / 모바일 최소 16px
- 캡션: 최소 13px
- 현재의 `font-serif`, italic 영문 eyebrow, 과도한 uppercase tracking은 제거하거나 편집 콘텐츠에만 제한한다.

## 10.3 그리드와 형태

- 데스크톱: 12열, 최대 콘텐츠 폭 1280px
- 태블릿: 8열
- 모바일: 4열, 좌우 여백 20px 이상
- 기본 카드 반경은 8–12px 범위에서 통일한다.
- 공공 정보 영역은 직선과 명확한 구획을 기본으로 하고 유기적 곡선은 Flow 표현에만 제한한다.
- 그림자보다 테두리, 여백, 배경 차이로 정보 계층을 만든다.

## 10.4 사진

- 실제 현장과 인물을 우선한다.
- 모든 사진은 CMS 또는 자산 매니페스트에서 출처·권리·대체 텍스트를 관리한다.
- 히어로는 `srcset`과 `sizes`를 제공하고 WebP/AVIF를 우선한다.
- 인물 얼굴이나 핵심 피사체가 모바일 crop에서 잘리지 않도록 focal point를 기록한다.
- 이미지가 실패해도 텍스트와 CTA를 사용할 수 있어야 한다.

## 12. 비기능 요구사항

### 12.1 접근성

- WCAG 2.2 AA와 국내 웹 접근성 지침을 목표로 한다.
- 키보드만으로 모든 메뉴, 필터, 모달, 검색, 카드 링크를 사용할 수 있어야 한다.
- 본문 대비는 4.5:1 이상, 큰 텍스트는 3:1 이상을 유지한다.
- 터치 대상은 최소 44×44px로 한다.
- 모달에 `role="dialog"`, `aria-modal`, 제목 연결, 포커스 트랩을 구현한다.
- `prefers-reduced-motion` 사용자는 비필수 애니메이션을 제거한다.
- 자동 갱신 정보는 스크린리더 사용자를 방해하지 않게 처리한다.
- 장식 이미지는 빈 `alt`, 정보 이미지는 목적 중심의 한국어 `alt`를 제공한다.

### 12.2 성능

- 모바일 p75 기준 LCP ≤ 2.5초
- INP ≤ 200ms
- CLS ≤ 0.1
- Lighthouse Performance 목표 ≥ 90
- 초기 JavaScript 번들 gzip 250KB 이하를 목표로 한다.
- 히어로 단일 이미지 전송량은 모바일 250KB 이하를 목표로 한다.
- 화면 아래 이미지는 lazy loading한다.
- 외부 Unsplash URL의 런타임 의존을 제거하고 승인된 자산 CDN 또는 로컬 최적화 자산을 사용한다.

### 12.3 보안·개인정보

- 외부 링크는 허용 도메인과 프로토콜을 검증한다.
- 뉴스레터·댓글 등 개인정보 입력 기능은 개인정보 수집 고지와 백엔드가 준비되기 전 노출하지 않는다.
- API 키를 클라이언트 번들에 포함하지 않는다.
- `GEMINI_API_KEY`는 현재 메인 홈페이지 개선 범위에서 사용하지 않는다.

### 12.4 호환성

- 최신 Chrome, Edge, Safari, Firefox의 최근 2개 주요 버전을 지원한다.
- 360px 모바일부터 1440px 이상 데스크톱까지 검증한다.
- 200% 텍스트 확대에서 정보와 CTA가 잘리거나 겹치지 않아야 한다.

### 기능

- [ ] 사용자 유형 선택이 지원사업 결과에 반영된다.
- [ ] 지원사업과 공지가 선택한 실제 상세로 연결된다.
- [ ] 신청 가능 여부와 실제 링크가 정확히 일치한다.
- [ ] 데이터에 기준일, 단위, 출처가 표시된다.
- [ ] 새로고침과 뒤로 가기 후에도 주요 상세·필터 상태가 유지된다.

- [ ] 키보드만으로 전체 핵심 업무를 완료할 수 있다.
- [ ] 모달의 포커스 진입·순환·복귀가 정상이다.
- [ ] 자동 접근성 검사에서 critical/serious 오류가 없다.

- [ ] 색상만으로 상태를 구분하지 않는다.

## 22. 최종 제품 방향

개선된 메인 홈페이지는 “aT가 어떤 기관인지 설명하는 긴 페이지”가 아니라 “사용자와 필요한 공공 서비스를 연결하는 첫 화면”이어야 한다.

이를 위해 공식 CI와 검증된 사진으로 신뢰를 세우고, 사용자 유형과 행동을 중심으로 정보 구조를 재편하며, 모든 데이터에 근거를 표시한다. 생산–유통–소비–수출을 잇는 Flow는 시각 장식이 아니라 실제 탐색 경험으로 구현한다.

최종 판단 기준은 페이지가 세련되어 보이는지가 아니라 다음 질문에 명확히 답하는지다.

> 농어업인, 기업, 수출기업, 국민이 이 화면에서 자신의 다음 행동을 빠르고 신뢰 있게 찾을 수 있는가?
